# Agent Instructions for chaos-create

## Quick Start

```bash
bun install              # Install dependencies
bun run dev              # Run CLI in watch mode
bun test                 # Run tests (Bun test runner)
bun run verify           # Lint + format check + typecheck
```

## Critical Details

**Runtime**: Bun >= 1.0.0 (required). The project uses Bun's built-in test runner and exec'd framework CLIs.

**Entry points**:

- CLI: `src/index.ts` (commander-based, shebang `#!/usr/bin/env bun`)
- Framework registry: `src/framework-registry.ts` (single source of truth for all supported frameworks)
- Tests: `src/index.test.ts` (Bun.test)

**Command workflow**: `lint → format:check → typecheck` (all run via `bun run verify`). Build runs verify first: `bun run build`.

**Testing**: Bun's native test runner (`bun test`). Test files use `.test.ts` alongside source. No Jest/Vitest.

**Key architecture**:

- The tool executes external framework CLIs (npm, bun, deno, flutter, etc.) via `child_process.exec`
- `FRAMEWORKS` array in `framework-registry.ts` defines all framework metadata including CLI commands, package managers, compatible libraries
- Library injection runs package manager commands directly (e.g., `bun add`, `npm install`)
- Feature generation writes `.tsx`/`.ts` files into generated projects under `src/features/` or `src/commands/`

## Non-Obvious Conventions

- **Module format**: ESM (`"type": "module"` in package.json), `moduleResolution: "bundler"` in tsconfig
- **Shebang preserved**: `src/index.ts` starts with `#!/usr/bin/env bun` - keep this line
- **Framework CLI args**: Use `{projectName}` placeholder in `framework-registry.ts`; replaced at runtime in `FrameworkGenerator.buildCommand`
- **Package manager per framework**: Not all use Bun. Angular uses `npm`; Flutter uses `flutter`; Deno frameworks use `deno`. Library injector handles each accordingly.
- **No git template support yet**: `GitTemplateManager` exists but `createFromTemplate` is incomplete/not wired to `create` command's `--template` flag (see `src/index.ts:207-209` - template path calls createFromTemplate but the flow has gaps)
- **Prettier config**: LF line endings, single quotes, 2-space tabs, printWidth 100, trailing commas ES5
- **ESLint**: Uses flat config, `@typescript-eslint` parser, unused-vars error with `argsIgnorePattern: '^_'`, `no-explicit-any` disabled

## Files to Touch

- Add frameworks: `src/framework-registry.ts`
- Add feature templates: `src/generators/feature-generator.ts` (getFeatureCode method)
- Change CLI commands: `src/index.ts` (commander setup) and `src/generators/framework-generator.ts` (execution)
- Tests: Add to `src/index.test.ts` or create new `*.test.ts` files

## Known Gaps / Quirks

- Template URL option (`--template`) is parsed but `createFromTemplate` may not fully work (untested, missing template pulling implementation details)
- Angular uses `ng` CLI which must be installed globally; Bun cannot invoke it if Angular CLI isn't on PATH
- Dev server commands map is hardcoded in `FrameworkGenerator.getDevCommand` - adding a framework requires updating this map
- No Windows-specific path handling issues observed (path module used), but exec'd commands use spaces in args - works because commands are constructed with proper spacing

## Do Not

- Do not change Bun as package manager (project is opinionated about Bun)
- Do not convert to CommonJS
- Do not add unused imports/vars (ESLint catches them)
- Do not update `package.json` version manually (not relevant yet - project is pre-release)
